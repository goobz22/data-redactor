📖 Configuration Guide

1. Enable/Disable Built-in Patterns

Toggle detection for specific data types:

"patterns": {
  "email": { "enabled": true, "strategy": "token" },
  "phone": { "enabled": false }
}

2. Choose Redaction Strategy

token → john@email.com becomes [EMAIL_1]
mask → john@email.com becomes **************
formatPreserving → john@email.com becomes xxxx@xxxxx.xxx

3. Add Custom Patterns

Create patterns for your specific data formats:

"patterns": {
  "custom": [
    {
      "name": "ticketId",
      "regex": "TICKET-\\d{5}",
      "strategy": "token",
      "sampleValue": "TICKET-12345"
    }
  ]
}
name What to call this pattern
regex Pattern to match (use \\\\ for backslashes)
strategy How to redact: token, mask, or formatPreserving
sampleValue Example for testing (optional)

4. Custom Entity Lists

Add specific names or terms to always redact:

"customEntities": {
  "companyNames": ["Acme Corp", "My Company Inc"],
  "customerNames": ["John Doe", "Jane Smith"]
}

5. Test Samples & Quality Testing

All built-in patterns have test samples to ensure accuracy:

📊 View Test Results: Go to Pattern Validation → Test Samples to:
  • Run patterns against curated test data
  • See quality scores (0-100)
  • Identify false positives and false negatives
  • View full sample content and expected matches

Each pattern includes 5 test samples covering common cases and edge cases.

Quality Score Breakdown:

● 80-100: High quality - Pattern works reliably across all test cases
● 60-79: Medium quality - Some issues detected, review recommended
● 0-59: Low quality - Significant issues, pattern needs improvement
